# IronCore — Дизайн-документ v1.0

> Версия 1.0 — 2026-06-09. Жанр: хардкорный инженерный мод.
> Один растущий костюм. Мастерская Старка. Survival-ворота через материалы и механики.

---

## Философия

Игрок не *коллекционирует* костюмы — он *строит и развивает один*.
Прогрессия не в «числа стали больше», а в «я починил настоящую проблему».

- **Обледенение на Mk2** → вынуждает найти золото-титановый сплав (Mk3)
- **Отравление палладием** → вынуждает синтезировать Старкиум (Mk6)
- **Заряд только на базе** → вынуждает строить и улучшать мастерскую
- **Износ каркаса** → вынуждает возвращаться домой, ремонтировать

Каждая проблема имеет каноническое решение. Прогресс — это решение проблем, а не рост цифр.

---

## Игровой цикл

```
Добыл материал → Обработал в мастерской → Собрал/перековал костюм → Обнаружил проблему → Исследовал решение → Повторить
```

Петля на каждый сеанс игры:
1. Вылетел на задание
2. Реактор расходует заряд
3. Вернулся на базу — зарядился
4. Починил износ (если нужно)
5. Исследуешь следующий апгрейд

## Эпохи прогрессии

### Индустриальная эпоха (Mk1 → Mk7)
Тони в гараже. Ручной крафт, уязвимости, несовершенные решения. Ощущение прогресса через преодоление конкретных проблем.

### Нано-эпоха (Mk42 → Mk50)
Другая эстетика и механика: нанотехнологии, вызов по частям, генератор на вибраниуме. Mk50 — финальная форма с нанощитом. Требует полного прохождения Индустриальной эпохи как ворота.

## Один каркас, который растёт

**Каркас (frame)** — предмет, идентифицирующий **тип** (Mk1, Mk2, Mk3…). Всё состояние костюма (прочность, модули, реактор, тепло, отравление) хранится в `SuitCapability` — **единственном источнике правды**. Каркас-предмет не хранит NBT-состояния сам по себе; он только говорит capability, какой тир сейчас активен.

Перековка на Сборочном верстаке:

```
Каркас Mk1 + материалы + чертёж → Каркас Mk2
Каркас Mk2 + материалы + чертёж → Каркас Mk3
...
```

При перековке capability мигрирует: старый каркас-предмет заменяется новым, **модули и реактор сохраняются** в capability — игрок вкладывается в *свой* костюм, а не крафтит новый.

> **Правило одного источника:** если данные есть в capability, их нет в NBT каркаса. Если данные есть в NBT каркаса — это ошибка архитектуры. Исключение: тип каркаса кодируется классом Item (Mk1FrameItem, Mk2FrameItem…), что само по себе и есть «NBT» тира.

### Тиры каркаса

Цепочка: каждый тир открывает новую проблему и решает проблему предыдущего.

| Тир | Ключевой материал | Новая проблема | Что решает |
|-----|------------------|----------------|------------|
| **Mk1** | Сталь | Хочу летать | — |
| **Mk2** | Сталь + компоненты | **Обледенение** на высоте | Даёт полёт |
| **Mk3** | **Золото-титановый сплав** | Палладий начинает **отравлять** | Решает обледенение |
| **Mk5** | Компакт | Громоздкость в быту | Портативность (кейс) |
| **Mk6** | Усиленный | Нужна большая мощность | Требует Старкиумовый реактор, даёт юнибим |
| **Mk7** | — | Нужен быстрый вызов | Ракеты на плечах |
| **Mk42** | — | Нужна максимальная гибкость | Вызов по частям |
| **Mk50** | **Нанотех** | — | Нанощит, нанотехнологии |

Палладиевый реактор становится доступен начиная с Mk2 (нужен для зарядки через FE). Отравление накапливается — это вынуждает дойти до Mk6 и установить Старкиумовый реактор.

Mk1 — escape-suit: нет полёта, угольное топливо прямо в реактор. Mk50 и Mk42 — Нано-эпоха с принципиально другими механиками управления.

## Мастерская (5 блоков)

Только costume-specific станки. Переработка руды — через ванильные рецепты и Forge Tags (совместимость с другими тех-модами, без конкуренции с GregTech/Create).

```
[Сборочный верстак]   — сборка/перековка каркаса, установка модулей, ремонт
[Ассемблер реактора]  — сборка реакторов из сердечника + корпуса
[Сплав-печь]          — золото-титановый сплав и другие costume-specific сплавы
[Стол исследований]   — открытие чертежей (ворота прогрессии)
[Зарядная станция]    — заряжает реактор через FE (принимает только FE извне)
```

### Сборочный верстак
Сердце мода. GUI: слот каркаса + сетка материалов + слоты модулей (просмотр). Действия:
- **Собрать** каркас из материалов по чертежу
- **Перековать** каркас в следующий тир (старый каркас + материалы + чертёж)
- **Установить / снять** модуль
- **Отремонтировать** каркас (материал каркаса → восстановление прочности)

### Ассемблер реактора
Принимает сердечник + корпус + компоненты. Выдаёт реактор нужного типа. Это единственное место, где собирается реактор.

### Сплав-печь
Двухвходовая (два лотка руды/слитков + топливо). Производит costume-specific сплавы: **Золото-Титановый сплав**, **Облегчённый каркасный сплав** и др. Не дублирует стандартные рецепты переплавки.

Совместима с Forge Tags: принимает `forge:ingots/gold`, `forge:ingots/titanium` — работает с рудой из других модов.

### Стол исследований
Потребляет материалы + время → разблокирует чертёж. Без чертежа рецепт не активен. Цепочка:
```
Полёт/Mk2 → Золото-Титан/Mk3 → Репульсоры → Синтез Старкиума → Старкиумовый реактор → Mk6/юнибим → Нанотех/Mk50
```

### Зарядная станция
Принимает **только FE** (Forge Energy). Не генерирует энергию сама. Откуда берётся FE:
- Ванильная генерация через адаптеры (мод-совместимость)
- **Ядро Дугового Реактора** (Arc Reactor Core) — отдельный блок IronCore, генерирует FE для базы

**Mk1:** реактор работает напрямую на угле (топливный слот прямо в реактор-предмете). Зарядная станция нужна начиная с Mk2.

---

## Ядро Дугового Реактора (Arc Reactor Core)

Отдельный блок — **генератор FE** для базы. Не путать с реактором-предметом.

- Потребляет топливо (уголь → палладиевые стержни → старкиумовые стержни)
- Выдаёт FE в прилегающие блоки (Зарядная станция, хранилища)
- Апгрейдится независимо от костюма
- Канонично: база Старка работает на своём дуговом реакторе

Реактор-предмет (носится в костюме) и Arc Reactor Core — разные сущности. Реактор-предмет **только хранит заряд**, не генерирует FE для базы.

---

## Система реактора

Реактор — предмет в слоте костюма. Хранит заряд (FE). Тип сердечника определяет:
- Ёмкость (сколько хранит)
- Скорость разряда
- Побочный эффект

### Типы реакторов

| Тип | Сердечник | Ёмкость | Эффект |
|-----|-----------|---------|--------|
| **Угольный** (Mk1) | Уголь | Очень мало | Нет (топливо прямо в реактор) |
| **Палладиевый** | Палладий | Средняя | **Отравление носителя** — нарастающий дебафф, снимается только снятием костюма |
| **Старкиумовый** | Старкиум | Высокая | Нет отравления. Требуется для полного потенциала Mk6 |
| **Вибраниумовый** | Вибраниум | Максимум | Нет |

**Важно:** Реактор-предмет не генерирует FE для внешнего мира. Это хранилище, не генератор.

**Mk6 и Старкиум:** Mk6 не содержит «встроенный» Старкиум — это противоречило бы модульности. Mk6 просто открывает доступ к юнибиму и рассчитан на высокую энергоёмкость: для полного потенциала нужен Старкиумовый реактор (устанавливается в слот реактора как обычно). С палладиевым реактором Mk6 работает, но ограниченно.

### Заряд только на базе
Пассивной регенерации нет. Реактор заряжается только через Зарядную станцию. Создаёт петлю «вылетел — выполнил задание — вернулся на базу». Без базы — нет полёта.

## Отравление палладием

При ношении костюма с палладиевым реактором:

| Стек | Эффект |
|------|--------|
| 1 | Слабость I, незначительное замедление |
| 2 | Слабость II, +10% расход энергии реактора |
| 3 | Тошнота, +25% расход энергии, помехи HUD (случайные мерцания данных) |
| 4 (критично) | Дрожание экрана, урон каждые 5с, HUD частично нечитаем, красное наложение |

Снимается: снять костюм + дать время спасть, или сменить на Старкиумовый реактор.

**Помехи HUD** на 3+ стеке — это не просто косметика: значения телеметрии начинают мигать и пропадать, что реально мешает следить за зарядом и обледенением. Это вынуждает игрока решить проблему, а не терпеть.

Это каноническая механика из фильма — Тони отравлялся своим же реактором.

## Обледенение (4 уровня)

Обледенение нарастает на Mk2 (без золото-титана). Скорость нарастания зависит от двух факторов:

```
icing_rate = height_factor + biome_cold_factor
```

- `height_factor`: линейно растёт начиная с Y=120 (0 на земле, максимум на Y≥200)
- `biome_cold_factor`: `+0.5×` в снежных биомах, `+0.25×` в горных, `0` в пустыне/тропиках

Это означает: в снежных горах обледенение наступает даже на средней высоте, в пустыне — позже и мягче.

| Уровень | Нарастание | Эффект |
|---------|-----------|--------|
| 1 — Иней | ~10с (норма) | Частицы льда, −5% эффективности реактора |
| 2 — Обмерзание | ~30с (норма) | Замедление полёта −20%, управление хуже |
| 3 — Обледенение | ~60с (норма) | Полёт нестабилен, угроза отказа |
| 4 — Критично | ~90с (норма) | **Система охлаждения отказывает**, авто-снижение |

Время «в норме» — открытый океан или равнина. В снежных горах уровни достигаются вдвое быстрее.

Mk3 (золото-титановый сплав) полностью снимает обледенение — это каноническое решение проблемы.

## Износ и ремонт

- Прочность каркаса хранится в `SuitCapability` (`frameDurability: Int`)
- Урон прочности: бой, жёсткие приземления, перегрузка при полёте
- Прочность = 0 → костюм инертен (базовая броня, способности off)
- Ремонт на Сборочном верстаке: материал каркаса → восстановление `frameDurability` в capability
- Ремонт не сбрасывает модули и реактор

---

## Аварийная посадка (emergency glide)

При истощении реактора в полёте — **не мгновенное падение**, а планирование:
- Скорость вертикального снижения ограничена (~2 б/т)
- Горизонтальная скорость сохраняется ещё 3–5 секунд
- HUD: «РЕАКТОР РАЗРЯЖЕН — АВАРИЙНАЯ ПОСАДКА»
- При приземлении — стандартный урон от падения (если не хватает высоты на торможение)

Это предотвращает внезапную смерть и даёт игроку шанс найти площадку для посадки.

## Телеметрия HUD

HUD отображает состояние в реальном времени. Данные группируются в «виджеты»:

| Виджет | Данные |
|--------|--------|
| **Реактор** | Заряд %, тип сердечника, температура |
| **Каркас** | Прочность %, тир (Mk N) |
| **Полёт** | Скорость (км/ч), высота, режим (HOVER/BOOST) |
| **Обледенение** | Уровень (0–4), иконка снежинки |
| **Отравление** | Уровень палладия (0–4), цвет нарастает к красному |
| **Системы** | Статус модулей (OK / WARN / FAIL) |

HUD рендерится клиентом на основе данных из `SuitCapability` (синхронизируется с сервера).

## Система модулей

Модули — предметы, вставляемые в слоты костюма (вкладка КОСТЮМ инвентаря). **Переживают перековку каркаса.** Каждый модуль имеет уровни (апгрейд на Сборочном верстаке).

### Базовые модули

| Модуль | Требует тир | Способность |
|--------|-------------|-------------|
| **Огнемётный модуль** | Mk1 | Единственное оружие escape-suit (Z) |
| **Репульсор** | Mk2 | Импульс руками (ПКМ) — первый «настоящий» модуль |
| **Ракетный ускоритель** | Mk2 | Ракеты (5 штук) |
| **Стабилизатор полёта** | Mk2 | Лучший контроль, меньше тепла |
| **Система охлаждения** | Mk2 | Снижает уровень обледенения |
| **Наведение** | Mk3 | Самонаводящиеся ракеты |
| **Юнибим** | Mk6 | Лазер из груди |
| **Нанощит** | Mk50 | Поглощение урона нанотехнологиями |

Mk1 — escape-suit: один примитивный огнемёт. Полноценный арсенал (репульсоры, ракеты) появляется на Mk2 вместе с полётом. Это делает переход Mk1→Mk2 ощутимым, а не косметическим.

### Отказы модулей

При критическом перегреве или низкой прочности модуль может **отказать**:
- Статус в HUD: FAIL (красный)
- Отказавший модуль не работает до ремонта на Сборочном верстаке
- Частичные отказы: репульсор отказал — остальные работают

## Материальная цепочка

Только costume-specific материалы. Стандартная руда (железо, золото, уголь) — через ванильные рецепты. Новые руды появляются там, где они нужны нарративно.

### Новые руды

| Материал | Слой | Редкость | Применение |
|----------|------|---------|------------|
| **Титан** | Y -20 до -64 | Обычная | Каркас Mk3+, Золото-Титан |
| **Палладий** | Y -50 до -64, Незер | Редкая | Реактор Mk1-Mk3, отравляет |
| **Вибраниум** | Эндерские острова | Очень редкая | Mk50, нанотех |

**Старкиум** — синтетический, не добывается. Синтезируется в Ассемблере реактора по чертежу.

### Forge Tags
Все рецепты используют Forge Tags:
- `forge:ingots/iron`, `forge:ingots/gold` — принимают слитки из любого мода
- `forge:ingots/titanium` — если другой мод добавил титан, он работает в Сплав-печи IronCore
- Это предотвращает дублирование руд при установке нескольких тех-модов

## Исследования / чертежи

Без чертежа рецепт на верстаке или в станке неактивен. Чертёж открывается на Столе исследований.

Цепочка обязательных чертежей:
```
[Каркас Mk1]
  → [Полёт/Mk2]
    → [Репульсоры] → [Ракеты]
    → [Золото-Титан] → [Каркас Mk3]
      → [Синтез Старкиума] → [Старкиумовый реактор]
        → [Каркас Mk6] → [Юнибим]
          → [Нанотех] → [Mk50]
```

Исследование занимает время (in-game тики) + потребляет материалы. Это органичная пауза в темпе прогрессии.

## Система полета

### Базовая механика
- **Hover (Парение):** Удержание высоты, низкое потребление энергии.
- **Boost (Ускорение):** Зажатый `CTRL`. Повышенная скорость, нагрев, расход энергии.

### Turbo Boost (Mk3+)
Механика сверхбыстрого перелета для дальних дистанций.

- **Условие активации:** Непрерывный полет на ускорении (W + CTRL) в течение 5 секунд.
- **Тумблер (Auto-Boost):** Клавиша `R` включает/выключает возможность активации турбо. Позволяет избежать случайного разгона в узких пространствах.
- **Эффекты:**
    - Увеличение максимальной скорости (+10-15 км/ч).
    - Увеличение FOV (+18-20%) для усиления чувства скорости.
    - Усиление визуальных эффектов: плотный поток синего пламени с искрами (Jet Stream).
- **Сброс:** Любое изменение вектора движения (отпускание W), отключение ускорения (CTRL) или перегрев мгновенно сбрасывают турбо-режим.

## Будущие обновления (Immersion Roadmap)

Эти функции запланированы для повышения эффекта присутствия («ощущения костюма»), но не входят в текущую итерацию.

### 1. Визуализация корпуса (First-Person Presence)
- **Руки в кадре:** При полете игрок видит перчатки костюма, выполняющие роль стабилизаторов.
- **Анимации:** Движение пальцев при стрельбе, отдача при работе репульсоров.

### 2. Свободный обзор (Freelook)
- **Клавиша ALT:** Позволяет вращать камеру на 180°, не меняя направление полета.
- **Цель:** Возможность осмотреть свой костюм в полете и оценить обстановку вокруг.

### 3. Интерфейс шлема (Helmet HUD)
- **Overlay:** Полупрозрачная маска шлема по краям экрана.
- **Динамика:** Легкое дрожание интерфейса при получении урона или высокой скорости.
- **Блики:** Эффект стекла шлема при взгляде на яркие источники света.

### 4. Звуковой ландшафт
- Процедурный шум ветра, зависящий от скорости.
- Механические звуки сервоприводов при поворотах.
- Звуковой сигнал («захлопывание шлема») при надевании костюма.

### 5. Визуализация тяги (Jet Stream Model)
- Замена стандартных частиц на анимированную 3D-модель пламени (mesh).
- Динамическое изменение длины и яркости струи в зависимости от скорости и режима (Turbo).
- Кастомные шейдеры для эффекта свечения и искажения воздуха.

## Архитектурные правила (для разработчиков)

1. **Физика полёта — сервер авторитарен, клиент интерполирует.**
   Клиент отправляет управляющие данные (направление, режим); сервер вычисляет позицию и скорость; клиент интерполирует между позициями для плавности. Это безопаснее в мультиплеере и устойчивее к десинку. В v0.1 (одиночный режим) допустимо считать на сервере без интерполяции, но архитектура должна предусматривать этот путь с самого начала — добавить интерполяцию позже намного проще, чем переписывать с клиентской физики.

2. **Каждый тир каркаса — отдельный класс Item.** Не NBT-поле `"tier"` в одном предмете. Отдельные классы гарантируют корректную работу рецептов, поисков и дропа.

3. **Огонь — через частицы и зону урона, не через реальные Fire-блоки.** Реальные блоки Fire меняют мир, мешают другим игрокам и сохраняются. Визуал — клиентские частицы; урон — серверный `hurtEntities` в зоне.

4. **Синхронизация костюма через capability, не через vanilla-слоты.** `SuitCapability` — единственный источник правды. Vanilla-слоты брони заполняются тик-копированием только для рендера. Это предотвращает дублирование в инвентаре и баги с БРОНЯ-вкладкой.

5. **Capability — единственный источник правды о состоянии костюма.** Прочность, заряд, тепло, уровень отравления, модули — всё в capability. Каркас-предмет хранит только тип через свой Java-класс. Если один и тот же параметр есть в двух местах — один из них лишний.

## Совместимость

- **Forge Energy (FE):** все станки используют FE. Работает с любым RF/FE-совместимым модом.
- **IItemHandler:** лотки станков доступны через `ICapabilityProvider`. Хопперы, трубы, AE2 работают без настройки.
- **Forge Tags:** рецепты через теги, не через конкретные Item ID. Другие тех-моды могут поставлять материалы.
- **Мультибблок не используется** — каждый станок — отдельный BlockEntity. Проще, понятнее, без синхронизации мультиблок-структур.

## Гараж: сцена первого запуска

Главный маркетинговый момент мода. Срабатывает **один раз** — при первом правом клике по Arc Reactor Core после его установки. Никакого авто-триггера на заход в мир.

### Триггер

Игрок ставит Arc Reactor Core в мастерской и кликает по нему ПКМ. Arc Reactor Core фиксирует флаг `firstActivation` в своём BlockEntity NBT — сцена больше не повторится.

### Что происходит

1. **Arc Reactor Core вспыхивает** — синее свечение, частицы энергии расходятся по полу мастерской
2. **Голограммы включаются поочерёдно** — 3D-проекции костюма (GeckoLib анимация медленного вращения) появляются над верстаками с задержкой 0.5с между каждой
3. **Джарвис отвечает** — голос (`.ogg`) и субтитры в чате:
   > *"Добрый вечер. Все системы в норме. Готов к работе."*

### Роль игрока

Игрок сам решает когда войти в образ. Фраза *"Папочка вернулся"* — это его реплика, не игровая механика. Мод создаёт атмосферу, не заставляет её проговаривать.

### Реализация

- `ArcReactorCoreTile` — хранит `firstActivation: boolean` в NBT
- При первом ПКМ: серверный пакет → клиент запускает `GarageWakeSequence`
- `GarageWakeSequence` — клиентский класс, управляет таймлайном эффектов (частицы → голограммы → звук)
- Голограммы — отдельные сущности (`HologramEntity`) без хитбокса, рендерятся через GeckoLib
- Звук регистрируется в `ModSounds`, файл: `sounds/jarvis_wake.ogg`

### Голограммы в мастерской (постоянно)

После первого запуска Arc Reactor Core работает как **источник питания голограмм** — пока он активен, над блоками мастерской висят голографические проекции:
- Над Сборочным верстаком — текущий каркас игрока (вращается)
- Над Столом исследований — иконка активного чертежа
- Над Зарядной станцией — индикатор уровня заряда реактора

Это чистая косметика, но именно она создаёт ощущение «мастерской Старка».

## Джарвис (Фаза 6)

Отдельный аддон **IronCore JARVIS** — не часть основного мода. Подключается через API.

- Голосовые / текстовые команды в чате (от лица Джарвиса)
- Умные подсказки: «Реактор на 12%, рекомендую вернуться на базу»
- Реактивные реплики на события: надел костюм, получил критический урон, реактор разряжен
- Телеметрия через Claude API (опционально)
- Не влияет на геймплей без аддона — основной мод работает самостоятельно

### Четыре фундаментальных системы — это α-scope

Если эти четыре работают стабильно — всё остальное надстройка. Если сломаны — никакой Mk50 не спасёт. Они и составляют первую веху.

```
1. SuitCapability     — canonical storage всего состояния костюма
2. ReactorItem        — хранение FE, тип сердечника, угольный топливный слот
3. FlightSystem       — сервер считает физику, клиент интерполирует
4. SuitHUD            — телеметрия на основе данных из capability
```

## План на будущее (Roadmap v0.2+)

### Система Чертежей (Blueprints)
Текущая система крафта через ванильный верстак и Стол кузнеца — это временное решение для Альфа-версии (v0.1). В будущем крафт будет полностью перенесен в **Сборочный стенд (Suit Station)**.
- **Интеграция чертежей:** В Сборочном стенде появится специальный слот для Чертежа. Без соответствующего чертежа (например, "Схема: Шлем Mk2") сборка или апгрейд детали будут невозможны.
- **Получение чертежей:**
  - **Исследования (Research):** Игрок сможет создавать чертежи на специальном "Столе исследователя", тратя ресурсы, опыт (XP) и время.
  - **Лут:** Редкие схемы (нано-технологии) будут генерироваться только в сундуках сложных данжей.
  - **Торговля:** В деревнях появится профессия Инженера, продающего базовые схемы.

### Гараж и физическая стойка для брони (Armor Stand)
Костюм перестанет быть просто набором предметов в инвентаре.
- **Стойка (Armor Gantry):** Броня будет храниться на физической стойке в мире. 
- **Модификация в мире:** Установка реактора и модулей будет происходить не через обычный GUI, а путем прямого взаимодействия с броней на стойке (или через продвинутый голографический интерфейс Стенда).
- **Надевание:** Чтобы надеть костюм, игрок должен будет встать на специальную платформу, после чего анимация (GeckoLib) "оденет" его в броню.
